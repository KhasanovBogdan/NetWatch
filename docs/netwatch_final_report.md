# Итоговый отчёт по проекту NetWatch (вариативная часть)

## Хронология выполнения работы

1. **Постановка задачи.** Определена тема вариативной части практики — реализация системы мониторинга сетевых ресурсов «с нуля». Тема согласована как индивидуальный проект в рамках вариативного раздела 2.2 задания на практику.
2. **Исследование.** Изучены принципы работы протоколов ICMP и TCP, рассмотрены существующие аналоги (Zabbix, Nagios, Prometheus, простые скрипты на Python и Bash), определены необходимые и достаточные функции для минимально жизнеспособного прототипа.
3. **Проектирование архитектуры.** Разработана трёхуровневая архитектура: уровень проверки (ping и TCP), уровень хранения (CSV-журнал), уровень представления (консоль и сайт проекта).
4. **Реализация прототипа.** Написан код на Python (`src/main.py`), реализующий проверку доступности узлов и портов, запись результатов в журнал.
5. **Тестирование.** Проведено тестирование на нескольких публичных сетевых узлах (Google DNS, Cloudflare DNS, GitVerse), проверена корректность обработки ошибок (тайм-аут, отказ в соединении, ошибка DNS).
6. **Документирование.** Составлен подробный технический туториал (`docs/netwatch_tutorial.md») с пошаговыми инструкциями, примерами кода и разделом о модификации проекта.
7. **Публикация.** Результаты проекта размещены на статическом сайте (`site/netwatch.html`) и в репозитории GitVerse.

Python 3, модули `socket`, `subprocess`, `csv`, `platform`, `datetime`, `pathlib`; HTML и CSS для представления результатов на сайте; Git и GitVerse для контроля версий.

## Проблемы и их решения

- **Различие синтаксиса ping между ОС.** Решено определением операционной системы через модуль `platform` и выбором соответствующих параметров команды.
- **Ложные срабатывания при недоступности по ICMP.** Решено добавлением отдельной TCP-проверки конкретных портов, так как ICMP может быть заблокирован межсетевым экраном даже при работающем сервисе.
